# Creality SPARKX สำหรับ Home Assistant

อินทิเกรชัน Home Assistant แบบทำงานในเครือข่ายท้องถิ่น (local) ไม่ต้องพึ่งคลาวด์
สำหรับเครื่องพิมพ์ 3 มิติ **Creality SPARKX i7**
(และน่าจะใช้ได้กับเครื่องพิมพ์ Creality รุ่นใหม่ๆ อื่นที่เปิด WebSocket API แบบเดียวกัน — ดู
[ความเข้ากันได้](#ความเข้ากันได้) ด้านล่าง)

ไม่ต้องสมัครบัญชี ไม่ต้องใช้คลาวด์ ไม่ต้องมี API key เครื่องพิมพ์ส่งสถานะของตัวเองผ่าน
WebSocket ธรรมดาในเครือข่ายท้องถิ่น อินทิเกรชันนี้แค่คอยรับฟังข้อมูลนั้น

**✅ ทดสอบและยืนยันแล้วว่าใช้งานได้จริง** บนเครื่องพิมพ์ Creality SPARKX i7 — เซนเซอร์
อุณหภูมิอัปเดตแบบเรียลไทม์ เอนทิตีลงทะเบียนถูกต้อง ไม่มีข้อผิดพลาดตอนติดตั้ง (ฟีเจอร์
กล้อง/ปุ่มควบคุม/ภาพตัวอย่างที่เพิ่มใน v1.2.0 ยังทดสอบผ่าน HTTP โดยตรงเท่านั้น ดู
[ข้อจำกัดที่ทราบอยู่แล้ว](#ข้อจำกัดที่ทราบอยู่แล้ว))

ฟีเจอร์กล้อง / ปุ่มควบคุมการพิมพ์ / ภาพตัวอย่างงานพิมพ์ / การ์ด Lovelace สำเร็จรูป ได้แรง
บันดาลใจมาจาก [`ha_creality_ws`](https://github.com/3dg1luk43/ha_creality_ws)
(อินทิเกรชันสำหรับตระกูล K1/K2/Ender 3 V3) แต่ implement แยกจากกันทั้งหมดเพื่อให้เข้ากับ
โปรโตคอลเฉพาะของ SPARKX i7 (Moonraker + WebRTC signaling ที่พอร์ต 8000 แทนที่จะเป็น
go2rtc)

## ฟีเจอร์

- **เซนเซอร์แบบเรียลไทม์** — อุณหภูมิหัวฉีด/แท่นพิมพ์ (ค่าปัจจุบัน + ค่าเป้าหมาย)
  ความคืบหน้าการพิมพ์ เลเยอร์ปัจจุบัน/เลเยอร์ทั้งหมด ชื่อไฟล์ที่กำลังพิมพ์ เวลาที่พิมพ์ไปแล้ว
  และเวลาที่เหลือ สถานะการพิมพ์ (ว่าง/กำลังพิมพ์/หยุดชั่วคราว/เสร็จแล้ว/ข้อผิดพลาด)
  ความเร็วพัดลมต่างๆ
- **ที่อยู่ IP ของเครื่องพิมพ์** — เซนเซอร์ diagnostic แสดง IP ที่เครื่องพิมพ์เชื่อมต่ออยู่
  สะดวกเวลาต้องเช็คว่าเครื่องพิมพ์อยู่ที่ IP ไหนโดยไม่ต้องไปเปิดหน้าจอเครื่อง
- **ชื่อเอนทิตีอ่านง่าย** — ทุกเซนเซอร์แสดงชื่อเฉพาะของตัวเอง (เช่น "อุณหภูมิหัวฉีด",
  "สถานะการพิมพ์") ไม่ใช่ชื่ออุปกรณ์ซ้ำๆ กันทุกแถวเหมือนก่อนหน้านี้
- **ถอดรหัสข้อผิดพลาดของเครื่องพิมพ์** — เมื่อเซนเซอร์ "ปัญหา" (Problem) ทำงาน จะมี
  แอตทริบิวต์เพิ่มเติมบอกรหัสข้อผิดพลาด (เช่น `FO2945`) พร้อมคำอธิบายเป็นภาษาอังกฤษ
  ที่แปลมาจาก[ตารางรหัสข้อผิดพลาดอย่างเป็นทางการของ Creality](https://wiki.creality.com/en/sparkx/error-code)
  ทำให้เอาไปใช้สร้างข้อความแจ้งเตือนที่มีความหมายได้ทันที (ดูตัวอย่าง Node-RED ด้านล่าง)
- **สถิติสะสมตลอดการใช้งาน** — วัสดุที่ใช้ไปทั้งหมด เวลาพิมพ์สะสมทั้งหมด (ปิดไว้เป็นค่าเริ่มต้น
  เปิดได้เองในหน้าตั้งค่าเอนทิตีถ้าต้องการ)
- **สวิตช์ไฟในเครื่อง** — เปิด/ปิดไฟของเครื่องพิมพ์ได้จาก HA
  ⚠️ ยืนยันแล้วว่าเครื่องพิมพ์จะไม่รับคำสั่งนี้ขณะกำลังพิมพ์งานอยู่ (ทดสอบโดยส่งคำสั่ง
  WebSocket ดิบตรงไปยังเครื่องพิมพ์โดยข้าม Home Assistant ไปเลย — สถานะไฟไม่เปลี่ยนและ
  เครื่องพิมพ์ไม่ส่งการยืนยันกลับมา) ดูเหมือนจะเป็นข้อจำกัดระดับเฟิร์มแวร์ ไม่ใช่บั๊กของ
  อินทิเกรชันนี้ ใช้งานได้ปกติเมื่อเครื่องว่าง
- **เซนเซอร์แบบ binary** — สถานะมีเส้นฟิลาเมนต์ สถานะปัญหา/ข้อผิดพลาด และเซนเซอร์การ
  เชื่อมต่อ เพื่อให้ automation ตอบสนองได้เมื่อเครื่องพิมพ์หลุดออฟไลน์
- **Local push** — ไม่มีการ polling เครื่องพิมพ์ส่งข้อมูลอัปเดตทันทีที่มีการเปลี่ยนแปลง
  ทำให้สถานะใน HA อัปเดตเกือบจะทันที
- **เชื่อมต่อใหม่อัตโนมัติ** — หากเครื่องพิมพ์รีบูต เปลี่ยนเครือข่าย หรือ HA รีสตาร์ท
  อินทิเกรชันจะพยายามเชื่อมต่อใหม่อยู่เบื้องหลังให้เอง
- **📷 กล้อง (camera entity)** — ดูภาพสดจากกล้องในตัวเครื่องพิมพ์ผ่าน WebRTC ได้ตรงใน
  Lovelace (พบว่าเครื่องพิมพ์เปิดเซิร์ฟเวอร์ signaling ของตัวเองที่พอร์ต `8000`) แสดงเฉพาะ
  เมื่อเครื่องพิมพ์รายงานว่ารองรับกล้อง (`webrtcSupport`) เท่านั้น — เครื่องพิมพ์บางรุ่น/
  บางเฟิร์มแวร์อาจไม่มีกล้อง ⚠️ ส่วนนี้ verify ได้แค่ระดับโปรโตคอล (ยิง SDP offer/answer
  ตรงๆ ผ่าน curl แล้วได้คำตอบถูกต้อง) แต่ยังไม่ได้เปิดดูภาพจริงผ่านหน้าจอ Lovelace เพราะ
  ทดสอบจากสภาพแวดล้อมที่ไม่มีเบราว์เซอร์ต่อกับ HA โดยตรง — ถ้าเปิดมาแล้วภาพไม่ขึ้น
  ช่วยเปิด issue แจ้งด้วย
- **🖼️ ภาพตัวอย่างงานพิมพ์ (image entity)** — ดึงภาพ thumbnail ที่ slicer ฝังไว้ในไฟล์
  gcode (พบ marker `; thumbnail begin WxH ...` ในไฟล์จริง) มาแสดงเป็นรูปตัวอย่างชิ้นงาน
  ที่กำลังพิมพ์ อัปเดตอัตโนมัติเมื่อเริ่มพิมพ์ไฟล์ใหม่
- **⏯️ ปุ่มควบคุมการพิมพ์** — Pause / Resume / Cancel สั่งผ่าน **Moonraker API**
  (พบว่าเครื่องพิมพ์รัน Klipper + Moonraker อยู่ภายใน เปิดพอร์ต `7125` ให้ใช้ REST API
  มาตรฐานที่มีเอกสารทางการ — ปลอดภัยและเสถียรกว่าการเดาคำสั่งใน WebSocket ของ Creality
  เอง และไม่ติดข้อจำกัด "คำสั่งถูกเมินขณะพิมพ์" แบบสวิตช์ไฟด้านล่าง)
- **CFS connected (binary sensor)** — บอกว่ามีการเชื่อมต่อกล่อง Creality Filament
  System (CFS) อยู่หรือไม่ (จากฟิลด์ `cfsConnect`) — ยังไม่มี sensor แยกตามกล่อง/ช่อง
  เพราะไม่มีฮาร์ดแวร์ CFS จริงให้ทดสอบโครงสร้างข้อมูล
- **ผูกกับสวิตช์ไฟจริง (ตัวเลือกขั้นสูง)** — ไปที่การตั้งค่าอินทิเกรชัน → **Configure**
  แล้วเลือกสวิตช์ปลั๊กไฟที่ใช้เปิด/ปิดเครื่องพิมพ์จริงๆ (ถ้ามี) เมื่อผูกไว้ เซนเซอร์ทั้งหมดจะ
  ขึ้น "ไม่พร้อมใช้งาน" ทันทีที่ปิดปลั๊ก แทนที่จะค้างค่าล่าสุดไว้ — ไม่บังคับ ข้ามได้ถ้าไม่มี
- **Diagnostics** — ไปที่หน้าอุปกรณ์ → เมนูจุดสามจุด → **Download diagnostics** เพื่อดู
  สถานะทั้งหมดจากเครื่องพิมพ์ พร้อมสถานะการเชื่อมต่อ WS/Moonraker สำหรับแนบไปกับ
  issue เวลามีปัญหา
- **Lovelace card สำเร็จรูป** — มีการ์ดแสดงสถานะ/ความคืบหน้า/อุณหภูมิ/ปุ่มควบคุม/
  ภาพตัวอย่าง/กล้อง แนบมาให้ในตัว ไม่ต้องติดตั้งอะไรเพิ่ม (ลงทะเบียนอัตโนมัติตอน HA
  เริ่มทำงาน) ดูตัวอย่างการตั้งค่า YAML ที่หัวข้อ [Lovelace card](#lovelace-card)
  ด้านล่าง

## การติดตั้ง

### ผ่าน HACS (custom repository)

1. HACS → Integrations → ⋮ (มุมขวาบน) → **Custom repositories**
2. เพิ่ม URL ของ repository นี้ เลือกประเภทเป็น **Integration**
3. ค้นหา **Creality SPARKX** แล้วติดตั้ง จากนั้นรีสตาร์ท Home Assistant

### ติดตั้งด้วยตนเอง

1. คัดลอกโฟลเดอร์ `custom_components/creality_sparkx` ไปไว้ในโฟลเดอร์
   `config/custom_components/` ของ Home Assistant
2. รีสตาร์ท Home Assistant

## การตั้งค่า

ไปที่ Settings → Devices & Services → **Add Integration** → ค้นหา **Creality
SPARKX** → กรอกที่อยู่ IP ภายในเครือข่ายของเครื่องพิมพ์ (เช่น `192.168.1.97`)

อินทิเกรชันจะตรวจสอบการเชื่อมต่อโดยเรียก endpoint `/info` ของเครื่องพิมพ์ก่อนตั้งค่าเสร็จ
ดังนั้นถ้า IP ผิดหรือเครื่องพิมพ์เอื้อมไม่ถึง จะขึ้นข้อผิดพลาดให้เห็นทันที

## ตัวอย่าง automation

```yaml
alias: "3D print finished"
trigger:
  - platform: state
    entity_id: sensor.i7_9120_print_state
    to: "completed"
action:
  - service: notify.mobile_app_your_phone
    data:
      title: "🎉 Print finished"
      message: "{{ state_attr('sensor.i7_9120_current_file','friendly_name') }}"
```

## ตัวอย่าง: แจ้งเตือนข้อผิดพลาดผ่าน Telegram ด้วย Node-RED

Home Assistant เวอร์ชัน 2026.8.3 ขึ้นไป บังคับให้ตั้งค่าอินทิเกรชัน `telegram_bot`
ผ่านหน้า UI (config flow) เท่านั้น ไม่รองรับการตั้งค่าแบบ YAML อีกต่อไป ถ้าใครใช้
Node-RED อยู่แล้ว วิธีที่สะดวกกว่าคือทำ flow แจ้งเตือนใน Node-RED แทน โดยอาศัย
แอตทริบิวต์ `code` / `description` ที่เซนเซอร์ "ปัญหา" (Problem, binary_sensor)
ของอินทิเกรชันนี้ให้มาแล้ว

ไฟล์ตัวอย่างพร้อมใช้งานอยู่ที่
[`examples/nodered-telegram-alert-flow.json`](examples/nodered-telegram-alert-flow.json)
— นำเข้าผ่านเมนู Node-RED → Import แล้วแก้ไข 3 จุดตามคอมเมนต์ในไฟล์:

1. เปลี่ยน `entity_id` ในโหนด "Trigger" ให้ตรงกับเซนเซอร์ Problem ของเครื่องคุณ
   (เช่น `binary_sensor.<ชื่อเครื่องพิมพ์>_problem`)
2. ตั้งค่าโหนด `telegram bot` ให้เป็นบอทของคุณเอง (bot token จาก
   [@BotFather](https://t.me/BotFather))
3. ใส่ `chatId` ของคุณเองในโหนดฟังก์ชัน "Format alert"

flow นี้ประกอบด้วย: โหนดดักฟังการเปลี่ยนสถานะของเซนเซอร์ Problem → โหนดฟังก์ชันที่
ดึงรหัสข้อผิดพลาดและคำอธิบายมาแต่งเป็นข้อความ → โหนดส่ง Telegram พร้อม debug node
ไว้เช็คโครงสร้างข้อมูลจริงเวลามีข้อผิดพลาดเกิดขึ้นครั้งแรก

## Lovelace card

การ์ดแนบมาในตัวอินทิเกรชันแล้ว (ไม่ต้องหาโหลดผ่าน HACS frontend แยก) หลังติดตั้ง/อัปเดต
อินทิเกรชันแล้วรีสตาร์ท HA เพิ่มการ์ดในแดชบอร์ดแบบ YAML ได้เลย (โหมด edit dashboard →
เพิ่มการ์ด → Manual):

```yaml
type: custom:creality-sparkx-card
title: SparkX i7
state_entity: sensor.sparkx_i7_print_state
progress_entity: sensor.sparkx_i7_print_progress
file_entity: sensor.sparkx_i7_current_file
time_remaining_entity: sensor.sparkx_i7_print_time_remaining
nozzle_temp_entity: sensor.sparkx_i7_nozzle_temperature
bed_temp_entity: sensor.sparkx_i7_bed_temperature
problem_entity: binary_sensor.sparkx_i7_problem
light_entity: switch.sparkx_i7_chamber_light
pause_entity: button.sparkx_i7_pause_print
resume_entity: button.sparkx_i7_resume_print
cancel_entity: button.sparkx_i7_cancel_print
camera_entity: camera.sparkx_i7_camera
image_entity: image.sparkx_i7_print_preview
```

ทุกช่องที่ลงท้ายด้วย `_entity` ไม่บังคับ (ยกเว้น `state_entity`) — ช่องไหนไม่ใส่หรือเอนทิตี
ไม่มีอยู่จริง แถว/ปุ่มที่เกี่ยวข้องจะไม่แสดง ใช้ชื่อเอนทิตีจริงของเครื่องคุณเอง (เช็คได้จาก
Settings → Devices & Services → Creality SPARKX → รายการเอนทิตี)

ถ้าตั้งทั้ง `camera_entity` และ `image_entity` การ์ดจะพยายามแสดง**ภาพสดจากกล้องจริง**
(ผ่าน `ha-camera-stream` ตัวเดียวกับการ์ดกล้องมาตรฐานของ HA) เป็นหลัก และโชว์ภาพตัวอย่าง
จากไฟล์ (slicer thumbnail) เป็นภาพเล็กข้างๆ ถ้ากล้องสดเชื่อมต่อไม่ติดภายใน 6 วินาที
(ดูข้อจำกัดที่ทราบอยู่แล้วด้านล่าง) การ์ดจะซ่อนพื้นที่กล้องอัตโนมัติแล้วขยายภาพตัวอย่างให้
เต็มพื้นที่แทน

**⚠️ ถ้าเปิดหน้า dashboard แล้วเจอกล่องแดง "Configuration error" ตรงตำแหน่งการ์ด**
(สลับกันเกิดบ้างไม่เกิดบ้างเวลา refresh) — พบระหว่างพัฒนาว่าเป็น **race condition ตอนโหลด
หน้าเว็บ** ไม่ใช่บั๊กของการ์ดเอง: การ์ดจะโหลดผ่าน `add_extra_js_url` ซึ่งบางครั้ง Lovelace
เริ่ม render view ก่อนสคริปต์การ์ดโหลดเสร็จ ยิ่งถ้าในเครื่อง HA เดียวกันมีการ์ด custom
ตัวอื่นที่โหลด/ลงทะเบียนซ้ำกัน (เช่น custom card สองตัวชื่อคล้ายกันที่แย่งชื่อ custom element
เดียวกัน) ยิ่งเพิ่มโอกาสให้ทั้งหน้าโหลดช้า/error สลับกันไป **refresh อีกครั้งแก้ได้เสมอ**
(ยืนยันแล้วว่าการ์ดใช้งานได้ปกติทุกครั้งหลัง refresh) เพิ่มความเสถียรได้อีกขั้นด้วยการลงทะเบียน
สคริปต์การ์ดเป็น Lovelace resource โดยตรง (นอกเหนือจากที่ auto-register ให้อยู่แล้ว): ไปที่
**Settings → Dashboards → เมนูจุดสามจุดมุมขวาบน → Resources → Add Resource** แล้วใส่ URL
`/creality_sparkx_card/creality-sparkx-card.js` เลือกประเภทเป็น **JavaScript Module**
บันทึกแล้วรีสตาร์ท HA ครั้งเดียว

## ความเข้ากันได้

อินทิเกรชันนี้พัฒนาและทดสอบกับ **Creality SPARKX i7** (รหัสรุ่นภายใน `F022`
เฟิร์มแวร์ `1.1.5.8`) ซึ่งเปิดให้ใช้งาน:

- `GET /info` — ข้อมูลประจำเครื่อง (mac, model, serial, เวอร์ชันเฟิร์มแวร์) ไม่ต้อง
  ยืนยันตัวตน
- `WS /ws` — WebSocket ธรรมดา ไม่ต้องยืนยันตัวตน ไม่ต้องมี handshake payload
  ข้อความแรกคือ snapshot สถานะทั้งหมด ข้อความถัดไปเป็นการอัปเดตบางส่วน (เฉพาะคีย์ที่
  เปลี่ยน) การส่ง JSON object พร้อมคีย์ที่ต้องการเปลี่ยน (เช่น `{"lightSw": 0}`) คือ
  การสั่งงานเครื่องพิมพ์
- `HTTP :7125` — **Moonraker** (Klipper's API server) เต็มรูปแบบ ไม่ต้องยืนยันตัวตน —
  `GET /server/info` ตอบกลับปกติ ยืนยันว่าเครื่องพิมพ์รัน Klipper อยู่ภายใต้ฝาครอบ UI ของ
  Creality เอง ใช้ endpoint มาตรฐาน `/printer/print/{pause,resume,cancel}` สำหรับปุ่ม
  ควบคุมการพิมพ์ (เปลี่ยนพอร์ตได้ในหน้า Configure ถ้าเครื่องคุณรันคนละพอร์ต)
- `HTTP :8000` — เซิร์ฟเวอร์ signaling กล้อง WebRTC ของเครื่องพิมพ์เอง (หน้า demo
  "Video On Demand" ที่ `/`) รับ SDP offer เป็น base64 ผ่าน `POST /call/webrtc_local`
  แล้วตอบ SDP answer กลับมาแบบ base64 เช่นกัน (non-trickle exchange)

อินทิเกรชันของชุมชนหลายตัวสำหรับ Creality รุ่น **K1 / K1 Max / K1C / K2**
(`ha_creality_ws`, `hass_creality_k1`, `ha-creality-lan` ฯลฯ) ใช้โครงสร้าง JSON
คล้ายกันมาก (`nozzleTemp`, `bedTemp0`, `printProgress`, `cfsConnect` ...) แต่เครื่อง
พิมพ์เหล่านั้นเปิดให้ใช้งานที่ **พอร์ต 9999** แทนที่จะเป็นพอร์ต HTTP ปกติแบบที่ใช้ในนี้
ถ้าเครื่องพิมพ์ของคุณตรงกับพอร์ต/โครงสร้างแบบนั้น อินทิเกรชันนี้อาจเชื่อมต่อไม่ได้ทันที —
ลองใช้โปรเจกต์เหล่านั้นแทน แต่ถ้าเครื่องพิมพ์ของคุณใช้พอร์ต 80 เหมือน SPARKX i7 ก็ควร
ใช้งานได้ ไม่ว่าจะกรณีไหนก็ตาม ช่วยเปิด issue พร้อมแนบผลลัพธ์จาก `/info` ของเครื่องคุณ
เพื่อช่วยติดตามความเข้ากันได้ด้วย

## ข้อจำกัดที่ทราบอยู่แล้ว

- **คำสั่งผ่าน WebSocket อาจถูกเมินขณะกำลังพิมพ์งาน** สวิตช์ไฟในเครื่อง (ผ่าน WS ของ
  Creality เอง) ดูเหมือนจะถูกเฟิร์มแวร์ของเครื่องพิมพ์ปฏิเสธขณะกำลังพิมพ์งานอยู่ WebSocket
  ยังคงส่งสถานะปกติมาเรื่อยๆ แต่ไม่มีการยืนยันการเปลี่ยนแปลงตามที่สั่ง และสถานะจริงก็ไม่
  เปลี่ยน ยืนยันแล้วโดยทดสอบส่งคำสั่ง `{"lightSw": 1}` แบบดิบตรงไปยังเครื่องพิมพ์ผ่าน
  WebSocket ธรรมดา ได้ผลลัพธ์เดียวกัน — จึงเป็นข้อจำกัดฝั่งเครื่องพิมพ์ ไม่ใช่สิ่งที่
  อินทิเกรชันนี้แก้ไขได้ ลองใหม่อีกครั้งเมื่อพิมพ์เสร็จหรือเครื่องว่างแล้ว **ปุ่ม Pause /
  Resume / Cancel ไม่ติดข้อจำกัดนี้** เพราะสั่งผ่าน Moonraker API คนละทางกัน
- **กล้องสด (WebRTC) เชื่อมต่อไม่สำเร็จกับเฟิร์มแวร์เครื่องนี้ในทางปฏิบัติ** ตรวจสอบผ่าน
  browser จริงแล้วพบว่า: ปลั๊กการ์ด (`<ha-camera-stream>` ของ HA เอง ตัวเดียวกับที่การ์ด
  กล้องมาตรฐานใช้) เรียก `async_webrtc_offer` ได้ถูกต้อง คำขอไปถึงเซิร์ฟเวอร์ signaling
  ของเครื่องพิมพ์จริง (`POST http://<host>:8000/call/webrtc_local`) แต่เซิร์ฟเวอร์ฝั่ง
  เครื่องพิมพ์ตัด connection ("Server disconnected" / connection reset) **เฉพาะตอนได้รับ
  SDP offer จริงจากเบราว์เซอร์** (มี ICE candidates, DTLS fingerprint, หลาย codec ครบ) —
  ทดสอบแล้วว่าไม่ใช่ปัญหาเรื่องขนาด payload (ส่ง SDP ปลอมขนาดใหญ่กว่าของจริงไปตรงๆ ด้วย
  curl/urllib เซิร์ฟเวอร์เครื่องพิมพ์ก็ตอบ 200 ปกติทุกครั้ง) และไม่ใช่ปัญหา keep-alive
  connection reuse ฝั่ง HA (แก้เป็นเปิด connection ใหม่ทุกครั้งแล้วก็ยังเจอ) จึงสรุปว่าเป็น
  ข้อจำกัดของโค้ด parse SDP ฝั่งเฟิร์มแวร์เครื่องพิมพ์เอง (มักเป็นโค้ดเขียนเองขนาดเล็ก ไม่ใช่
  WebRTC stack มาตรฐาน) ที่รับมือกับ SDP จริงจากเบราว์เซอร์ไม่ได้เต็มรูปแบบ — ไม่ใช่สิ่งที่
  แก้ได้จากฝั่งอินทิเกรชัน HA ระหว่างที่ยังหาทางแก้ไม่ได้ การ์ดจะลองเชื่อมต่อภาพสด 6 วินาที
  แล้วถ้ายังไม่ติดจะซ่อนพื้นที่กล้องอัตโนมัติและโชว์ภาพตัวอย่างจากไฟล์ (thumbnail) เต็มพื้นที่
  แทน ไม่ปล่อยกล่องดำค้างไว้ ถ้าใครเจอเฟิร์มแวร์รุ่น/เครื่องอื่นที่เชื่อมต่อกล้องสดสำเร็จ
  ช่วยแจ้งผ่าน issue ด้วย จะได้ปรับปรุงตามเงื่อนไขจริง
- **ไม่มี per-slot CFS sensor** เพราะไม่มีฮาร์ดแวร์ Creality Filament System จริงให้
  ทดสอบโครงสร้างข้อมูล มีแค่ binary sensor บอกว่าเชื่อมต่ออยู่หรือไม่โดยรวม

## คำชี้แจง

โปรเจกต์นี้เป็นโปรเจกต์อิสระของชุมชน ไม่มีความเกี่ยวข้องหรือได้รับการรับรองจาก Creality
สร้างขึ้นจากการวิเคราะห์ทราฟฟิก API ภายในเครื่องพิมพ์เอง (reverse-engineering) ไม่ได้ใช้
บัญชีคลาวด์หรือเอกสารจากผู้ผลิตแต่อย่างใด การควบคุมเครื่องพิมพ์ (ตอนนี้มีแค่สวิตช์ไฟ)
เป็นการให้บริการแบบ best-effort กรุณาอย่าพึ่งพาอินทิเกรชันนี้กับงานที่เกี่ยวข้องกับความ
ปลอดภัย
